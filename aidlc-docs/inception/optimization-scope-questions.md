## Q1：本轮迭代要不要把全部 12 个差距一次做完？

**背景**：差距清单很长（参见 `gap-analysis.md`），从模型重构、电商式选购、图册重写到分享增强，工作量大。

**选项**：

- **A** — 一次做完全部（P0 + P1 + P2 + P3 + P4 + P5）
  _一口气做完 12 个差距，时间长、风险大，但一步到位_

- **B** — 分两批：第一批做 P0+P2（数据模型重构 + 详情页电商式选购 + 报价单一键加入）；第二批再做 P1+P3+P4+P5
  _建议方案：先打通核心商业闭环，让产品/算价/报价能落地_

- **C** — 分三批：① P0+P2（核心链路）→ ② P1（图册搜索重写）→ ③ P3+P4+P5（文档/案例/分享）
  _最稳妥的拆分，每批做完都可独立验证_

- **D** — 只做最关键的 P0+P2，其余暂缓（P1/P3/P4/P5 之后再说）
  _紧急止损，先把"产品配置→算价→加单"链路跑通_

## Q5：图册筛选项里"动态属性聚合"的口径如何定？

**选项**：

- **A** — 仅聚合 `ProductConfigDimension.options`（即配置维度的所有选项值），按 dimension_key 分组展示为筛选项
  _最自然，与配置选择器一致_

- **B** — 聚合 `ProductConfigDimension.options` + 旧 `ProductConfig.attributes` 的 JSON keys（兼容旧数据）

- **C** — 不做动态聚合，所有筛选项都由后端硬编码维护（关闭这个特性）
  _最快但偏离需求_

- **D** — A 方案 + 长/宽/高 MECE 区间 + 价格 MECE 区间合并展示
  _最完整_
